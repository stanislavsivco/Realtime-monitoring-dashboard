- Security config hardening (branch 53_SecurityHardening):
  - AGENT_API_KEY required at startup with minimum 32 bytes (empty key no longer accepts empty header)
  - AgentApiKeyFilter strips context path and trailing slashes before matching protected paths
  - Unauthenticated requests return the same JSON ErrorResponse as the rest of the API (RestAuthenticationEntryPoint, SecurityErrorWriter)
  - FRONTEND_ORIGIN accepts a comma-separated list, trailing slashes are removed, wildcard is rejected

  - Fake metric generator interval changed from 5 s to 10 s
- Device delete and registration fixes (branch 54_feature/device-delete-and-registration-fixes):
  - Deleting a device removes its metrics, alerts and threshold first (bulk JPQL deletes in one transaction), previously failed on foreign keys
  - Deleting a non-existent device returns 404 and no WebSocket event is sent
  - Device name is unique (DB constraint + service check), duplicates return 409 (DeviceNameAlreadyExistsException)
  - Concurrent agent registration with the same hostname returns the existing device instead of creating a duplicate
  - DataIntegrityViolationException mapped to 409 in GlobalExceptionHandler without leaking DB details
  - Agent re-registers automatically when its cached device ID returns 404
  - agent/.machine_id removed from Git and added to .gitignore
  - H2 test dependency and DeviceServiceIntegrationTest (real database checks for delete, unique name, registration)
- Alert fixes:
  - findAlertsFiltered typo fixed, GET /api/alerts without a severity filter no longer returns an empty page
  - createAlert skips duplicates (unresolved alert with the same severity for the device) and broadcasts new alerts to /topic/alerts
  - AlertServiceTest extended
- Metric ingest validation and live device status (branch 56_feature/metric-ingest-validation):
  - New IngestMetricRequestDTO for /api/devices/ingest: deviceId required, cpu, ram and disk required between 0 and 100, latency and network not negative (400 with fieldErrors)
  - Metric timestamp always set by the server, a client timestamp is ignored (a wrong agent clock can no longer block OFFLINE detection)
  - Device status changes (ONLINE, WARNING, CRITICAL, back from OFFLINE) are broadcast to /topic/devices
  - startDate after endDate returns 400 for metric history and analytics, analytics with only endDate uses the 7 days before it
  - Reading thresholds no longer writes to the database, defaults are returned until an admin saves custom values
  - Device name, type, location and agent hostname limited to 255 characters (400 instead of a database error)
  - Swagger descriptions for metric history, analytics and ingest
  - ThresholdServiceTest added, metric, controller and DTO tests extended
- WebSocket authentication and origin restriction (branch 61_feature/websocket-authentication-and-origin-restriction):
  - /ws accepts only origins from FRONTEND_ORIGIN (other origins get 403 on the handshake and on SockJS)
  - STOMP CONNECT requires a valid JWT in the Authorization header (StompAuthChannelInterceptor), missing, invalid or expired tokens and deleted users are rejected
  - SUBSCRIBE is allowed only after login and only to /topic/** destinations
  - SEND from clients is rejected, so nobody can publish fake metrics or alerts to other users
  - Frontend WebsocketService sends the token from AuthService in the CONNECT frame and does not connect without a token
  - StompAuthChannelInterceptorTest added
- Metric retention and login rate limiting (branch 66_feature/metric-retention-and-login-rate-limiting):
  - Metrics older than METRIC_RETENTION_DAYS (default 7, minimum 1) are deleted every hour in batches of 1000 (MetricRetentionService)
  - Indexes on metrics.timestamp and (device_id, timestamp)
  - SIMULATION_ENABLED switch (default false): DataSeeder and the fake metric generator (now MetricSimulator) run only when it is true, so production gets no demo data
  - DataSeeder log fixed (it said "seeding continues" while it skipped seeding)
  - Rate limiting per IP address: POST /api/auth/login 10 per minute, POST /api/auth/register 5 per hour (configurable), 429 with Retry-After and ErrorResponse (AuthRateLimitFilter, RateLimiter)
  - server.forward-headers-strategy native: the client IP is taken from X-Forwarded-For only behind an internal proxy, so the header cannot be spoofed from outside
  - New variables documented in .env.example, tests for retention (unit + H2), simulation switch, rate limiter and filter
- Local database credentials from .env (PR 51, Stano):
  - docker-compose.local-db.yml reads LOCAL_DB_USERNAME and LOCAL_DB_PASSWORD, Compose stops when they are missing
  - .env.example explains how to run with Neon or the local database, including down -v after a password change
- OpenAPI operationIds for client generation (branch 67_feature/openapi-operation-ids):
  - Every endpoint has an explicit, stable operationId (getDevices, createDevice, getMetricHistory, ...)
  - Every 4xx response uses the ErrorResponse schema, 401 is added to secured endpoints and 403 to ADMIN-only endpoints automatically (OpenApiConfig customizers), 429 documented on login and register
  - Paging exposed as page, size and sort query parameters, success responses documented as application/json
  - POST /api/devices returns 201 Created
  - docs/openapi.json committed, OpenApiSpecTest fails when it is outdated, ControllerOperationIdTest fails when an endpoint has no operationId
  - Checked that openapi-generator (typescript-angular) generates the client from docs/openapi.json
